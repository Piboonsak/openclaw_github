How-To Dropdown

1) Configure DNS records (ทีมเราทำเอง)
  1. Login DNS provider dashboard ด้วย account ทีมเรา
  2. ตั้ง A records: uat.bwcacc.biz, app.bwcacc.biz, demo.bwcacc.biz
  3. ตั้ง TTL ของ record ที่ใช้ deploy = 300 วินาที
  4. เพิ่ม CAA record: 0 issue "letsencrypt.org"
  5. ตรวจว่าแต่ละ host ชี้ IP เป้าหมายถูกต้องก่อน save
  6. Export DNS zone backup เก็บเป็น infra/dns-zone-backup.txt
2) Verify DNS propagation
  1. ตรวจผ่าน Cloudflare resolver และ Google resolver
  2. ผลลัพธ์ต้องเท่ากับ IP เป้าหมายของแต่ละ env
dig @1.1.1.1 uat.bwcacc.biz +short nslookup uat.bwcacc.biz 8.8.8.8
3) Issue SSL certificate with Certbot
  1. ยืนยันว่า DNS resolve แล้วก่อนรัน certbot
  2. ใช้ certbot standalone mode (ไม่ใช่ --nginx) เพราะ nginx รันใน Docker container ไม่ใช่ host service
  3. Port 80 ต้องว่างตอน issue ครั้งแรก (ยังไม่มี nginx container)
  4. หรือใช้ script: ssh root@VPS 'DOMAIN=uat.bwcacc.biz bash -s' < scripts/infra/setup-certbot.sh
sudo apt-get update sudo apt-get install -y certbot sudo certbot certonly --standalone --cert-name uat.bwcacc.biz -d uat.bwcacc.biz --non-interactive --agree-tos -m admin@yahwan.biz --no-eff-email sudo systemctl enable certbot.timer && sudo systemctl start certbot.timer sudo certbot renew --dry-run
4) Validate auto-renew and health checks
  1. รัน dry-run cert renew
  2. ทดสอบ redirect และ health endpoints
sudo certbot renew --dry-run curl -I http://uat.bwcacc.biz curl -s https://uat.bwcacc.biz/health curl -s https://uat.bwcacc.biz/api/health
5) SSH hardening and deploy user
  1. สร้างผู้ใช้ deploy และให้สิทธิ์ที่จำเป็น
  2. แก้ค่า PermitRootLogin no ใน sshd_config
  3. reload/restart sshd แล้วทดสอบ login ด้วย deploy user
sudo adduser deploy sudo usermod -aG sudo,docker deploy sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config sudo systemctl restart ssh
6) Certificate expiry monitoring setup
  1. เพิ่ม monitor ใน Uptime Kuma หรือใช้ cron monitor อย่างน้อย 1 วิธี
  2. กำหนด threshold แจ้งเตือนก่อนหมดอายุอย่างน้อย 30-40 วัน
