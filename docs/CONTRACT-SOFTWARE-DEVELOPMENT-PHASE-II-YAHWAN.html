ข้อ 1. วัตถุประสงค์

ผู้ว่าจ้างตกลงว่าจ้าง และผู้รับจ้างตกลงรับจ้างพัฒนาระบบ LedgerFlow / AI Pre-Accounting Copilot สำหรับสนับสนุนงานเตรียมข้อมูลก่อนลงบัญชี (Pre-Accounting) แบบ Human-in-the-Loop ครอบคลุมการอัปโหลดเอกสาร การประมวลผล OCR/AI การตรวจทานข้อมูล การกำหนดผังบัญชีและ template export การส่งออกข้อมูล CSV/Excel และการเตรียมระบบให้พร้อมใช้งานบนสภาพแวดล้อม UAT/Production ตามขอบเขต Phase II ที่ระบุในสัญญานี้

ข้อ 2. ขอบเขตงาน Phase II — Combined Package

Phase II เป็นงานพัฒนาต่อยอดจาก PoC เพื่อให้ระบบพร้อมใช้งานจริงในระดับ MVP โดยเน้นการนำระบบที่พิสูจน์แนวคิดแล้วขึ้นสู่สภาพแวดล้อม UAT/Production, เพิ่มความสามารถด้าน template/export, เพิ่มหน้าจอ admin ที่จำเป็น, เพิ่ม line item extraction และ inventory/stock report และปรับความแม่นยำจากปัญหาที่พบจริงระหว่าง PoC

2.1 Requirement และผลส่งมอบของ Phase II

Requirement Group รายละเอียดงาน ผลส่งมอบที่ผู้ว่าจ้างจะได้รับ
A. Base Install / Foundation วางฐานระบบสำหรับใช้งานจริงจาก PoC ได้แก่ database, storage, background worker, health check, backup baseline, deployment path และการจัดสภาพแวดล้อม UAT/Production ระบบพร้อม deploy และรองรับการทดสอบ/ใช้งานแบบแยกสภาพแวดล้อม
B. Accuracy Edge Cases ปรับ logic จากปัญหาที่พบจริงใน PoC เช่น WHT, การแยก VAT included/excluded, เอกสารที่มีเส้นตารางรบกวน OCR และโหมดดูเอกสารกว้างขึ้นสำหรับตรวจทาน ผล OCR/AI น่าเชื่อถือขึ้น พร้อม flag จุดที่ควรให้คนตรวจ
C. Template + Admin MVP* เพิ่มหน้าจอจัดการ template export (รองรับ format Express Accounting), clone template รายบริษัท, เลือก/เรียง/เปลี่ยนชื่อ column, login, role ขั้นต้น, company profile, COA import, import รายชื่อผู้จำหน่ายและลูกค้า และ settings ที่จำเป็น ผู้ใช้จัดรูปแบบ export เองได้ ลดการแก้ code เมื่อ format ลูกค้าเปลี่ยน
D. Line Item + Inventory / Stock Report สกัดรายการสินค้า (line item) จากเอกสาร, จัดเตรียมข้อมูล inventory, ส่งออกรายงาน stock สินค้า และ Sales Tax Report ลดภาระงานจัดทำรายงาน stock ที่ต้องทำด้วยคน ระบบช่วยดึงข้อมูลและจัดรูปแบบให้
E. UAT / Go-Live / Handover จัดเตรียม UAT, เปิด production, smoke test, handover, user/admin guide และสรุปวิธีใช้งานหลังส่งมอบ ลูกค้าสามารถเริ่มทดสอบและใช้งานจริงตาม workflow ที่ตกลง
F. Document Workflow ปรับ workflow หลักตั้งแต่อัปโหลดเอกสาร, เลือกไฟล์, ประมวลผล, ตรวจผลสแกน, ตรวจ mapping บัญชี และ export มี flow การทำงานครบตั้งแต่รับเอกสารจนได้ไฟล์ export

2.3 สถาปัตยกรรมระบบ (System Architecture)

ระบบ Phase II ใช้สถาปัตยกรรมแบบ Web Application ผ่าน HTTPS โดยผู้ใช้งานเข้าผ่าน Browser ระบบประมวลผลเอกสารบน Cloud/VPS, จัดเก็บข้อมูลในฐานข้อมูลและ storage ที่กำหนด, และส่งออกข้อมูลเป็น CSV/Excel สำหรับนำไปใช้งานต่อในระบบบัญชีของผู้ว่าจ้าง

ภาพอ้างอิงจาก PoC เดิม: แสดงแนวคิดการใช้งานจากฝั่งผู้ใช้ อัปโหลดเอกสารเข้า Cloud และดาวน์โหลด CSV/Excel เพื่อนำไปใช้งานต่อ

ข้อจำกัดความรับผิดชอบ: ส่วน "Express On-Prem Server" ในแผนภาพ PoC เป็นเพียงการแสดงทางเลือกการนำ CSV เข้าระบบบัญชีของผู้ว่าจ้างเท่านั้น ไม่อยู่ในขอบเขตงาน Phase II ผู้รับจ้างไม่รับผิดชอบต่อ Express, การบันทึกบัญชี หรือการนำข้อมูลเข้าระบบ GL ใด ๆ

4.3 ภาษีมูลค่าเพิ่มและภาษีหัก ณ ที่จ่าย

  • ราคาข้างต้นยังไม่รวมภาษีมูลค่าเพิ่ม (VAT) เว้นแต่ระบุเป็นอย่างอื่น หากผู้รับจ้างมีสถานะจดทะเบียน VAT ให้เรียกเก็บ VAT ตามอัตราที่กฎหมายกำหนด
  • ผู้ว่าจ้างที่เป็นนิติบุคคลสามารถหักภาษี ณ ที่จ่ายตามอัตราและหลักเกณฑ์ที่กฎหมายกำหนด และต้องออกหนังสือรับรองหัก ณ ที่จ่ายให้ผู้รับจ้าง
  • รายละเอียดบัญชีรับชำระเงินของผู้รับจ้างให้ระบุในเอกสารแนบท้ายหรือใบแจ้งหนี้
  • หากผู้ว่าจ้างผิดนัดชำระเงินเกิน 15 วัน ผู้รับจ้างมีสิทธิ์หยุดงานหรือระงับบริการชั่วคราวจนกว่าจะได้รับชำระครบถ้วน

ข้อ 8. หน้าที่ของผู้ว่าจ้าง

  1. จัดส่งตัวอย่าง CSV/Excel ที่สามารถ import เข้า Express Accounting ได้จริง รวมถึง column order, encoding และ delimiter ที่ต้องการ
  2. จัดส่งผังบัญชี (Chart of Accounts / COA), รายชื่อผู้จำหน่าย (Vendor List) และรายชื่อลูกค้า (Customer List) รวมถึงข้อมูลบริษัทที่เกี่ยวข้อง เช่น ชื่อบริษัท เลขประจำตัวผู้เสียภาษี สาขา และข้อมูล mapping ที่ต้องใช้
  3. จัดส่งตัวอย่างเอกสารจริงหรือเอกสารทดสอบที่ได้รับอนุญาตให้ใช้สำหรับ OCR/AI testing ตามจำนวนและรูปแบบที่เพียงพอต่อการทดสอบ
  4. ให้ข้อมูล DNS, domain, hosting หรือสิทธิ์ที่จำเป็นต่อการตั้งค่า UAT/Production ตามที่ตกลง
  5. ทดสอบ UAT และส่ง feedback ภายในระยะเวลาที่คู่สัญญากำหนดร่วมกัน หากล่าช้า ระยะเวลาส่งมอบอาจเลื่อนออกไปตามจำนวนวันที่ล่าช้า
  6. ตรวจสอบความถูกต้องของข้อมูลที่ระบบสกัดก่อนนำไปใช้ด้านบัญชี ภาษี หรือการเงินทุกครั้ง

ข้อ 9. ข้อจำกัดและข้อสงวนสิทธิ์ด้าน AI/OCR

ระบบ LedgerFlow / AI Pre-Accounting Copilot ใช้เทคโนโลยี AI/OCR ในการอ่านและสกัดข้อมูลจากเอกสาร ซึ่งอาจมีความคลาดเคลื่อนจากคุณภาพเอกสาร รูปแบบเอกสาร ภาษา ตาราง เส้นกริด หรือข้อจำกัดของโมเดล ผู้ใช้งานต้องตรวจสอบและยืนยันข้อมูลก่อน export หรือนำไปใช้งานทุกครั้ง
  1. ระบบนี้เป็นเครื่องมือช่วยจัดเตรียมข้อมูลก่อนลงบัญชี (Pre-Accounting) ไม่ใช่ระบบบัญชีเต็มรูปแบบ
  2. ระบบนี้ไม่ใช่และไม่ทดแทน Express Accounting หรือซอฟต์แวร์บัญชีอื่นใด
  3. ระบบนี้ไม่ทำหน้าที่บันทึกบัญชีจริง, post GL เข้า ERP, ยื่นภาษี, หรือรับรองความถูกต้องทางบัญชี/ภาษี
  4. ผู้รับจ้างไม่รับผิดชอบต่อความเสียหายที่เกิดจากการนำข้อมูลที่ยังไม่ได้ตรวจสอบไปใช้ตัดสินใจทางบัญชี ภาษี หรือการเงิน

ข้อ 10. การส่งมอบและการยอมรับงาน

  1. ผู้รับจ้างจะส่งมอบงานผ่าน UAT environment, Production environment, เอกสารคู่มือ หรือไฟล์ส่งมอบตามความเหมาะสมของแต่ละ milestone
  2. ผู้ว่าจ้างต้องแจ้ง defect หรือ feedback ในขอบเขต UAT ภายในระยะเวลาที่ตกลงร่วมกัน
  3. หากผู้ว่าจ้างไม่แจ้ง feedback ภายในเวลาที่กำหนดโดยไม่มีเหตุอันสมควร ให้ถือว่างานใน milestone นั้นได้รับการยอมรับโดยปริยาย
  4. Defect หมายถึงการทำงานที่ไม่ตรงกับ scope หรือ acceptance criteria ที่ตกลงไว้ ไม่รวม requirement ใหม่หรือการเปลี่ยนแปลงวิธีทำงานภายหลัง

ข้อ 11. การดูแลระบบและ MA Support

การดูแลระบบหลัง Go-Live รวมอยู่ในค่าบริการรายเดือนตามข้อ 5 โดยครอบคลุมการสนับสนุนออนไลน์ การตรวจสอบ incident, bug triage, monitoring, backup operation เบื้องต้น และการปรับ template ตามจำนวนที่ระบุ

11.2 SLA — Service Level Agreement

รายการ มาตรฐานบริการ
Uptime Target 99.5% ต่อเดือน สำหรับส่วน Web Application ที่ผู้รับจ้างดูแลโดยตรง ไม่รวม scheduled maintenance และ third-party outage
Response Time Critical: ภายใน 4 ชั่วโมงทำการ / High: ภายใน 1 วันทำการ / Normal: ภายใน 3 วันทำการ
Bug Fix Target Critical: เริ่มแก้ภายใน 24 ชั่วโมงหลังรับทราบและได้รับข้อมูลครบ / Normal: ภายใน 3-5 วันทำการตามความซับซ้อน
RTO (Recovery Time Objective) 24 ชั่วโมง สำหรับเหตุขัดข้องร้ายแรงที่ต้องกู้ระบบจาก backup หรือ redeploy service
RPO (Recovery Point Objective) 3 ชั่วโมง สำหรับข้อมูลระบบที่อยู่ภายใต้ backup policy ที่ผู้รับจ้างดูแล

Scheduled maintenance: ผู้รับจ้างจะแจ้งล่วงหน้าไม่น้อยกว่า 48 ชั่วโมงหากมีการปิดระบบหรือ restart service ที่อาจกระทบผู้ใช้งาน เว้นแต่เป็นเหตุเร่งด่วนด้านความปลอดภัยหรือ incident ที่ต้องแก้ไขทันที

ข้อยกเว้น SLA: เหตุสุดวิสัย, ปัญหา internet/network ของผู้ว่าจ้าง, ปัญหาจาก cloud/VPS provider, domain/DNS provider, OCR/LLM/AI API provider, การใช้งานผิดวิธี, ข้อมูลนำเข้าผิดปกติ, หรือการแก้ไขระบบโดยบุคคลภายนอก ไม่ถือเป็น downtime หรือ defect ที่ผู้รับจ้างต้องรับผิดตาม SLA

ข้อ 12. ทรัพย์สินทางปัญญาและใบอนุญาต (IP & License)

  1. กรรมสิทธิ์ของระบบ: ระบบ LedgerFlow / AI Pre-Accounting Copilot และส่วนประกอบที่ผู้รับจ้างพัฒนาหรือมีอยู่ก่อนโครงการนี้ รวมถึง algorithm, source code, documentation, prompt, template engine, automation, reusable component, know-how, workflow design และ configuration framework เป็นทรัพย์สินทางปัญญาของผู้รับจ้าง เว้นแต่คู่สัญญาจะตกลงเป็นอย่างอื่นเป็นลายลักษณ์อักษร
  2. ใบอนุญาตใช้งาน: เมื่อผู้ว่าจ้างชำระค่าจ้างครบถ้วนตามงวดที่ถึงกำหนด ผู้ว่าจ้างได้รับสิทธิ์ใช้งานระบบแบบ non-exclusive, non-transferable และ revocable เฉพาะเพื่อใช้ในกิจการภายในของผู้ว่าจ้างและบริษัทลูกค้าของผู้ว่าจ้างตามขอบเขตที่ตกลงในสัญญานี้
  3. ข้อห้าม: ผู้ว่าจ้างจะไม่นำระบบหรือส่วนประกอบของระบบไปขาย ให้เช่า แจกจ่าย ให้บริการต่อบุคคลภายนอก ทำซ้ำ ดัดแปลง สร้าง derivative works, reverse engineer, พยายามถอดรหัส หรือใช้เพื่อพัฒนาระบบแข่งขันกับผู้รับจ้าง เว้นแต่ได้รับอนุญาตเป็นลายลักษณ์อักษรจากผู้รับจ้าง
  4. ข้อมูลของผู้ว่าจ้าง: เอกสารต้นฉบับ ข้อมูลธุรกิจ ผังบัญชี ข้อมูลลูกค้า และข้อมูลที่ผู้ว่าจ้างอัปโหลดเข้าระบบยังคงเป็นทรัพย์สินของผู้ว่าจ้าง ผู้รับจ้างจะไม่นำข้อมูลดังกล่าวไปใช้นอกเหนือจากการพัฒนา ทดสอบ ส่งมอบ และดูแลระบบตามสัญญานี้
  5. Open-source / third-party components: library, service, AI/OCR API, cloud/VPS service หรือ component ของบุคคลภายนอกอยู่ภายใต้เงื่อนไข license และ service terms ของผู้ให้บริการนั้น ๆ ซึ่งคู่สัญญาต้องปฏิบัติตามเท่าที่เกี่ยวข้อง
  6. งานส่งมอบเฉพาะลูกค้า: export template, mapping configuration, report configuration หรือ rule ที่สร้างขึ้นจากข้อมูลของผู้ว่าจ้าง ให้ผู้ว่าจ้างมีสิทธิ์ใช้งานภายในกิจการตามสัญญานี้ แต่ framework และเครื่องมือที่ใช้สร้างยังคงเป็นของผู้รับจ้าง

ข้อ 13. การรักษาความลับและข้อมูลส่วนบุคคล

  1. คู่สัญญาต้องรักษาความลับของข้อมูลทางธุรกิจ เอกสารบัญชี ข้อมูลลูกค้า ข้อมูลระบบ และข้อมูลอื่นที่ได้รับจากอีกฝ่าย
  2. ผู้รับจ้างจะใช้ข้อมูลของผู้ว่าจ้างเฉพาะเพื่อการพัฒนา ทดสอบ ส่งมอบ และดูแลระบบตามสัญญานี้เท่านั้น
  3. หากมีข้อมูลส่วนบุคคล คู่สัญญาจะร่วมกันกำหนดวิธีเก็บ ใช้ ลบ หรือจำกัดการเข้าถึงให้เหมาะสมกับกฎหมายและความจำเป็นของโครงการ

ข้อ 14. การลงนามออนไลน์และเอกสารอิเล็กทรอนิกส์

คู่สัญญาตกลงให้การลงนามในสัญญาหรือเอกสารที่เกี่ยวข้องด้วยลายมือชื่ออิเล็กทรอนิกส์, การลงนามบนไฟล์ PDF, การสแกนเอกสารลงนาม, การยืนยันผ่านอีเมล, หรือการยืนยันเป็นลายลักษณ์อักษรผ่านช่องทางอิเล็กทรอนิกส์ที่คู่สัญญาตกลงใช้ มีผลผูกพันคู่สัญญาเช่นเดียวกับการลงนามในเอกสารต้นฉบับบนกระดาษ

เอกสารอิเล็กทรอนิกส์ สำเนา PDF หรือสำเนาสแกนที่มีลายมือชื่อหรือหลักฐานการยืนยันของคู่สัญญา สามารถใช้เป็นหลักฐานแห่งข้อตกลงและการอนุมัติได้

ข้อ 15. การยกเลิกสัญญา

  1. หากฝ่ายใดฝ่ายหนึ่งผิดสัญญาอย่างมีนัยสำคัญ อีกฝ่ายต้องแจ้งเป็นลายลักษณ์อักษรเพื่อให้แก้ไขภายใน 15 วัน
  2. หากไม่แก้ไขภายในกำหนด ฝ่ายที่ไม่ได้ผิดสัญญามีสิทธิ์ยกเลิกสัญญาหรือระงับการให้บริการตามสมควร
  3. ค่าจ้างที่ถึงกำหนดหรือชำระแล้วสำหรับงานที่ดำเนินการแล้วไม่สามารถเรียกคืนได้ เว้นแต่คู่สัญญาจะตกลงเป็นอย่างอื่นเป็นลายลักษณ์อักษร
  4. การยกเลิกสัญญาไม่กระทบต่อหน้าที่รักษาความลับ การชำระหนี้ค้าง และข้อจำกัดความรับผิดที่เกิดขึ้นก่อนวันยกเลิก

ข้อ 16. ข้อจำกัดความรับผิด

  1. ผู้รับจ้างรับผิดชอบเฉพาะการพัฒนาระบบตามขอบเขตและ acceptance criteria ที่ตกลงไว้ในสัญญานี้
  2. ผู้รับจ้างไม่รับผิดชอบต่อความเสียหายทางอ้อม กำไรที่สูญหาย ความเสียหายจากการใช้งานข้อมูลโดยไม่ตรวจสอบ หรือความเสียหายจากระบบภายนอกที่ไม่ได้อยู่ภายใต้การควบคุมของผู้รับจ้าง
  3. ความรับผิดรวมของผู้รับจ้างภายใต้สัญญานี้ไม่เกินค่าจ้างที่ผู้ว่าจ้างชำระจริงให้ผู้รับจ้างสำหรับ Phase ที่เกี่ยวข้องกับเหตุแห่งความรับผิดนั้น

ข้อ 17. เหตุสุดวิสัย

คู่สัญญาไม่ต้องรับผิดในความล่าช้าหรือการไม่สามารถปฏิบัติตามสัญญา อันเกิดจากเหตุสุดวิสัยหรือเหตุที่อยู่นอกเหนือการควบคุมโดยสมเหตุสมผล เช่น ภัยธรรมชาติ สงคราม โรคระบาด คำสั่งหน่วยงานรัฐ เหตุขัดข้องของ cloud provider, AI provider, network, domain registrar หรือบริการภายนอกอื่น ทั้งนี้ฝ่ายที่ได้รับผลกระทบต้องแจ้งให้อีกฝ่ายทราบภายในเวลาอันสมควร

ข้อ 18. กฎหมายที่ใช้บังคับและข้อพิพาท

  1. สัญญานี้อยู่ภายใต้กฎหมายไทย
  2. หากเกิดข้อพิพาท คู่สัญญาจะเจรจาโดยสุจริตเพื่อหาข้อยุติร่วมกันก่อน
  3. หากไม่สามารถตกลงกันได้ คู่สัญญาอาจนำข้อพิพาทเข้าสู่ศาลไทยที่มีเขตอำนาจ หรือกระบวนการระงับข้อพิพาทอื่นที่ตกลงร่วมกัน
