Step 5: Map Review — Field-by-Field Control Matrix

The table below defines how each accounting field is sourced, validated, reviewed, and finalized at Step 5 (Map Review) before posting approval.

Field (Map Review) Source Validation Logic Human Action Final Use
document_type D2 classifier + extraction context Must match accepted type group for selected rule Approve or reclassify document type Selects rule candidate scope in D4
rule_id D4 score-based matching result Highest score + specificity tie-break Accept or force fallback to review rule Determines posting pattern template
account_code (line-level) D3 resolver tiers + company COA Code must exist in company chart_of_accounts Edit account mapping when flagged Used for final GL posting/export
amount_field mapping Extraction fields + selected rule entries Numeric parseable and bound to correct line side Adjust mapped source field if needed Controls debit/credit amounts per line
debit_total / credit_total Generated postings aggregate Absolute delta <= 0.01 Must resolve mismatch before confirm Posting gate (cannot confirm unbalanced)
flags (unresolved_rule, ambiguous_rule, needs_human_account_pick) D4 + D3 + balance checks Any risk flag requires explicit reviewer attention Clear flag by correction or reject posting Audit trail and reviewer accountability
express_gl payload TASK-503 interface output Schema fields present and posting lines complete Approve for export handoff Feeds Step 6 export and downstream accounting import

Key Decision Details Used in Implementation

D4 Rule Matching

Use score-based selection with specificity tie-break to ensure deterministic posting behavior.

Control: unresolved or tie results are explicitly routed to review workflow.

D3 Variable Account Resolver

Hybrid pipeline: deterministic cache first, fuzzy matching second, LLM assist third, human confirmation always available.

Control objective: reduce recurring LLM calls while preserving accounting reliability.

D6 Company Rule Loading

Per-company YAML under rules/{company_id}/rule_coa.yaml with shared global defaults.

Control objective: strict company isolation with repeatable generation and auditable updates.
