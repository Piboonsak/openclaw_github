§0 Why this redesign

The original Epic 1 (loop-detection + evidence + pre-commit) is too narrow. The AI-Dev-Factory spec proved that only 5 of 12 agent pain points become hard gates with that scope — the other 7 stay “prompt-only” and agents bypass them. This redesign keeps the same 3 task IDs but rescopes each to deliver one full governance layer:

  • TASK-101 — State + Questionnaire (issue form → single source of truth)
  • TASK-102 — 4 CI hard gates (Scope, Evidence, Risk Router, Quality)
  • TASK-103 — Local enforcement + Failure classifier + Model tier policy

Result: every pain point closes with a hard gate or enforceable policy. After Epic 1, Epics 2–7 become agent-driven by default.

§4 TASK-102 Four-Layer CI Gate Pipeline

Owner: DevOps / Governance · Risk: HIGH · Duration: ~3 days · Closes: pain points 4, 5, 8, 9, 12

Purpose

Implement the 4 security layers as CI hard gates in a single workflow agent_gate.yml. Every PR must pass all four to be merge-eligible.

Layer A — Scope Lock

scripts/gates/check_scope.sh

Input:  PR diff vs base branch + state file
Output: exit 0 if every changed file
        ∈ allowed_scope AND ∉ forbidden_scope
        exit 1 with per-file reason otherwise

Always-forbidden defaults applied even if empty: .env*, **/secrets/**, **/private_data/commercial/**.

Layer B — Evidence Lock (with AC↔test binding)

scripts/gates/check_evidence.py

Requires .agent/evidence/<TASK-ID>/evidence.md with 3 sections:

## Commands Executed
$ pytest tests/ml/test_ocr.py -v
$ docker compose run --rm backend pytest ...

## Raw Output
<verbatim stdout/stderr>

## Acceptance Criteria
- [x] ac_ocr_runs (test_ocr_runs_on_sample) — PASSED
- [x] ac_conf_score (test_confidence_attached) — PASSED

For each AC with test field, greps Raw Output for <test_fn> .* PASSED. Integration AC (id int_*) additionally requires a docker command line.

Layer C — Human Decision Router (HDR)

scripts/gates/hdr_gate.py

Reads PR files + state.risk_tier
HIGH/CRITICAL  → must carry label
                 'approved-by-human'
Auto-bump to HIGH if PR touches:
  - src/backend/auth/**
  - src/backend/payments/**
  - migrations/**
  - config/openclaw.prod.json5
  - .github/workflows/**  (gate self-edit)

Layer D — Quality Pipeline

Inline in agent_gate.yml:

- ruff check src/ scripts/ tests/
- mypy scripts/ src/backend
       --ignore-missing-imports
- pytest -q --maxfail=1
- bash   scripts/gates/check_scope.sh
- python scripts/gates/check_evidence.py
- python scripts/gates/hdr_gate.py

Uses concurrency: gate-${{ github.event.pull_request.number }} so re-runs cancel stale checks.

§5 TASK-103 Local Enforcement + Failure Classifier + Model Policy

Owner: DevOps / Governance · Risk: MEDIUM · Duration: ~2 days · Closes: pain points 6, 9 (local), 10, 11

Purpose

Stop bad commits before they reach CI (saves CI minutes + token cost). When CI does fail, classify the failure so the fix-agent gets a narrow retry scope instead of the whole repo.

Deliverables

.github/workflows/
└── classify-on-failure.yml         # on gate fail → classify → PR comment

min_action_check.py (Action Lock)

Pass if at least one staged file matches:
  src/**, tests/**, scripts/**, config/**, docker/**
Fail if everything staged is in:
  .agent/logs/**, **/*.md (notes only),
  .agent/state/** (without code)
Override: state.status=BLOCKED AND
          evidence has '## Blocker' section

classify_failure.py

Reads a CI log → emits JSON:

{
  "category": "unit_test",
  "escalate_to_human": false,
  "suggested_fix_scope": [
    "src/backend/ml/extractor.py",
    "tests/ml/test_extractor.py"
  ],
  "evidence_excerpt": "FAILED ... AssertionError: ..."
}

§6 Execution Order (3 Days)

Day 1 AM TASK-101 schema + agent_state.py + issue template Day 1 PM TASK-101 intake-sync.yml + project board automation Day 2 TASK-102 layers A, B, C + agent_gate.yml workflow Day 3 AM TASK-103 min_action_check + pre-commit hook Day 3 PM TASK-103 classify_failure + classify-on-failure.yml Day 3 EOD End-to-end smoke test using a real seed issue (TASK-501 OCR)

After Day 3, Epic 5 (Core Parser) becomes the first real consumer — every TASK-5xx issue is created via the questionnaire, dispatched to Copilot Agent (tier-2a, $0), and merged only when all 4 gates are green.

§7 Definition of Done (Epic 1)

  • All three task ACs above pass — pytest tests/governance -q green
  • One seed issue (TASK-501 OCR) flows end-to-end: questionnaire → state file → project card → Copilot PR → 4 gates pass → auto-merge → board moves to Done
  • One deliberately bad PR is blocked at each of the 4 layers in turn (evidence stored in .agent/evidence/EPIC-1/)
  • docs/AGENT-SKILL-CATALOG.md updated with the new gate scripts
  • AGENTS.md references the questionnaire and points agents at .agent/README.md
