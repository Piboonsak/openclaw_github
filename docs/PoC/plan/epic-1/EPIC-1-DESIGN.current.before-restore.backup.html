§0 What changed in this design

This Epic 1 design is now explicit about the real operating mode: users normally work from VS Code, NongKung, Copilot Chat, and GitHub MCP/GraphQL. GitHub Issue UI is supported, but it is not the primary path.

Current repo reality: task-intake.yml, intake-sync.yml, intake_to_state.py, and policy-based GraphQL assignment are design targets for TASK-101. They are not assumed to already exist.

Design code: intake_to_state.py
def parse_issue_body(body: str) -> dict:
    fields = extract_q_sections(body, expected=["Q1", "Q2", "Q3", "Q4", "Q5", "Q6", "Q7", "Q8"])
    state = {
        "task_id": parse_task_id(fields["Q1"]),
        "risk_tier": parse_enum(fields["Q2"], ["LOW", "MEDIUM", "HIGH", "CRITICAL"]),
        "model_tier": parse_model(fields["Q3"]),
        "allowed_scope": parse_globs(fields["Q4"]),
        "forbidden_scope": merge_default_forbidden(parse_globs(fields["Q5"])),
        "acceptance_criteria": parse_ac_rows(fields["Q6"]),
        "max_loops": clamp_int(fields["Q7"], default=5, maximum=10),
        "escalation_policy": parse_enum(fields["Q8"], ["human", "ai-debate", "stop"]),
        "status": "PENDING",
        "run_count": 0,
        "last_action": "intake-created"
    }
    validate_state_or_raise(state)
    return state
Design code: MCP / GraphQL policy dispatch
def dispatch(issue, state, policy):
    route = resolve_route(
        epic=issue.label_value("epic"),
        phase=issue.label_value("phase"),
        priority=issue.label_value("priority"),
        risk=state["risk_tier"],
        policy=policy,
    )
    sync_labels(issue, {"model": route.model, "agent": route.agent, "risk": state["risk_tier"].lower()})
    move_project_status(issue, map_state_to_column(state["status"]))
    if can_assign_copilot(issue, state, route):
        graphql_assign_copilot(issue.node_id)
        move_project_status(issue, "In Progress")
    else:
        move_project_status(issue, "Ready for Trial")
        comment(issue, route.block_reason)

§7 Definition of Done

  • Seed issue TASK-501 flows from MCP issue creation to state file, board sync, Copilot assignment, PR, gates, merge, deploy, health, and closed-with-proof.
  • A bad PR is blocked by scope, evidence, and HDR gates.
  • Bypass labels auto-expire within 24 hours and leave audit comments.
  • Board mapping check catches renamed/missing project columns.
  • HIGH/CRITICAL tasks require human approval before merge.

§7.5 Fast Pilot Readiness - ทำแค่นี้รอดไหม?

คำตอบสั้น: รอดสำหรับ PoC เร่งด่วนได้ ถ้าเปิด 3 guardrails บังคับทันที และยอมให้ส่วนที่เหลือเป็น shadow mode ชั่วคราว. ไม่รอดถ้าปล่อยให้ bypass, issue intake, หรือ board automation เป็น manual ล้วน.

Minimum guardrails ที่ต้อง active ตั้งแต่วันแรก

Guardrailต้องทำจริงถ้าไม่ทำจะติดอะไร
Forbidden pathsHard fail for private_data/**, .env*, secrets, commercial dataCustomer data or secrets leak into PR/evidence
Evidence requiredEvery PR needs raw output or manual proof bound to ACAI says done without running anything
Bypass expiresbypass:governance expires after 24h with audit commentTemporary bypass becomes permanent default

อะไรยังติดเยอะ

High friction

  • task-intake.yml and intake-sync.yml are not created yet.
  • MCP issue body must match the Issue Form contract exactly.
  • Copilot assignment needs GraphQL and KI-075 precheck.
  • Projects v2 column rename can break automation unless mapping is checked daily.
  • Workflow state commits must avoid trigger loops.

Low friction

  • Keep governance code isolated in .agent/, scripts/governance/, and scripts/gates/.
  • Let AI draft Q1-Q8, but require human confirmation for scope + AC.
  • Hard fail forbidden paths and missing evidence immediately.
  • Run HDR/AI business review in shadow mode until false positives are understood.

Rollout switchboard

Decision: shadow mode is only calibration. Production-ready Epic 1 means state sync, evidence gate, board mapping, bypass expiry, and close-with-proof are enforced.
