§0 What changed in this design

This Epic 1 design is now explicit about the real operating mode: users normally work from VS Code, NongKung, Copilot Chat, and GitHub MCP/GraphQL. GitHub Issue UI is supported, but it is not the primary path.

Current repo reality: task-intake.yml, intake-sync.yml, intake_to_state.py, and policy-based GraphQL assignment are design targets for TASK-101. They are not assumed to already exist.

Original design had 3 tasks (101/102/103) covering 12 pain points. This revision adds TASK-104 (PR→Production Closure) to close the 6 remaining deployment/verify pain points, bringing the total to 18/18. Layer C HDR is upgraded from human-decision-router to AI Decision Router — AI reviews business vs code logic first, human only when HIGH/CRITICAL.

How it works · How to use · How to implement

How it works

ทุกครั้งที่ user พิมพ์ “ทำ TASK-NNN…” ใน VS Code/NongKung, AI orchestrator จะ draft Q1-Q8 → user ยืนยัน → MCP/GraphQL สร้าง issue พร้อม body มาตรฐาน → workflow intake-sync.yml ดึง body มา parse ผ่าน intake_to_state.py → เขียน .agent/state/<TASK-ID>.json (validate ด้วย _schema.json) → policy_dispatch.py อ่าน model-policy.yaml เพื่อตัดสินว่าจะส่งให้ Copilot tier ไหน → ถ้า ready ใช้ assign_copilot.py (GraphQL only, KI-075) assign bot.

Output: state file ที่ AI agent อ่านได้ตลอดเวลา + Projects v2 card อยู่ column ตามจริง + label sync ตรง.

How to use (operator)

  1. เปิด VS Code → chat บอก: สร้าง TASK-501 OCR extraction
  2. AI draft Q1-Q8 ใน chat → ตรวจ scope/AC แล้วพิมพ์ confirm
  3. รอ MCP สร้าง issue + intake-sync.yml รัน (~30s) จะเห็น label status:ready
  4. เช็ค .agent/state/TASK-501.json ว่าถูก commit เข้า branch แล้ว
  5. Bot จะรับงานเอง (LOW/MEDIUM auto, HIGH/CRITICAL รอ approve)

How to implement (developer)

  1. เขียน .agent/state/_schema.json (JSON Schema draft-2020-12, ดู Q1-Q8 contract)
  2. สร้าง scripts/agent_state.py CLI: init / update / get / lock + file lock
  3. สร้าง .github/ISSUE_TEMPLATE/task-intake.yml ทั้ง 8 fields + required
  4. สร้าง scripts/intake_to_state.py regex parse + validate via schema
  5. สร้าง .github/workflows/intake-sync.yml trigger issues.opened/edited
  6. สร้าง scripts/governance/policy_dispatch.py + assign_copilot.py (GraphQL mutations)
  7. เขียน tests ใน tests/governance/ ครอบทุก AC (~7 tests)

Purpose

How it works

Output: PR ที่ผ่าน gate การันตี — ไม่ออกนอก scope, ไม่ fake done, business ตรง intent, code รันได้จริง.

§7.5 Fast Pilot Readiness — ทำแค่นี้รอดไหม?

คำตอบสั้น: รอดสำหรับ PoC เร่งด่วนได้ ถ้าเปิด 3 guardrails บังคับทันที และยอมให้ส่วนที่เหลือเป็น shadow mode ชั่วคราว. ไม่รอดถ้าปล่อยให้ bypass, issue intake, หรือ board automation เป็น manual ล้วน.

Minimum guardrails ที่ต้อง active ตั้งแต่วันแรก

Guardrailต้องทำจริงถ้าไม่ทำจะติดอะไร
Forbidden pathsHard fail for private_data/**, .env*, secrets, commercial dataCustomer data or secrets leak into PR/evidence
Evidence requiredEvery PR needs raw output or manual proof bound to ACAI says done without running anything
Bypass expiresbypass:governance expires after 24h with audit commentTemporary bypass becomes permanent default

อะไรยังติดเยอะ

High friction

  • task-intake.yml and intake-sync.yml are not created yet.
  • MCP issue body must match the Issue Form contract exactly.
  • Copilot assignment needs GraphQL and KI-075 precheck.
  • Projects v2 column rename breaks automation unless mapping is checked daily.
  • Workflow state commits must avoid trigger loops.

Low friction

  • Keep governance code isolated in .agent/, scripts/governance/, scripts/gates/.
  • Let AI draft Q1-Q8, but require human confirmation for scope + AC.
  • Hard fail forbidden paths and missing evidence immediately.
  • Run HDR/AI business review in shadow mode until false positives are understood.
