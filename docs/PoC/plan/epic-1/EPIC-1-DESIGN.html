§0 What changed in this design

This Epic 1 design is now explicit about the real operating mode: users normally work from VS Code, NongKung, Copilot Chat, and GitHub MCP/GraphQL. GitHub Issue UI is supported, but it is not the primary path.

Current repo reality: task-intake.yml, intake-sync.yml, intake_to_state.py, and policy-based GraphQL assignment are design targets for TASK-101. They are not assumed to already exist.

Original design had 3 tasks (101/102/103) covering 12 pain points. This revision adds TASK-104 (PR→Production Closure) to close the 6 remaining deployment/verify pain points, bringing the total to 18/18. Layer C HDR is upgraded from human-decision-router to AI Decision Router — AI reviews business vs code logic first, human only when HIGH/CRITICAL.

Design code: intake_to_state.py
def parse_issue_body(body: str) -> dict:
    fields = extract_q_sections(body, expected=["Q1","Q2","Q3","Q4","Q5","Q6","Q7","Q8"])
    state = {
        "task_id":            parse_task_id(fields["Q1"]),
        "risk_tier":          parse_enum(fields["Q2"], ["LOW","MEDIUM","HIGH","CRITICAL"]),
        "model_tier":         parse_model(fields["Q3"]),
        "allowed_scope":      parse_globs(fields["Q4"]),
        "forbidden_scope":    merge_default_forbidden(parse_globs(fields["Q5"])),
        "acceptance_criteria":parse_ac_rows(fields["Q6"]),
        "max_loops":          clamp_int(fields["Q7"], default=5, maximum=10),
        "escalation_policy":  parse_enum(fields["Q8"], ["human","ai-debate","stop"]),
        "status": "PENDING", "run_count": 0, "last_action": "intake-created"
    }
    validate_state_or_raise(state)
    return state
Design code: MCP / GraphQL policy dispatch
def dispatch(issue, state, policy):
    route = resolve_route(
        epic=issue.label_value("epic"),   phase=issue.label_value("phase"),
        priority=issue.label_value("priority"), risk=state["risk_tier"], policy=policy,
    )
    sync_labels(issue, {"model": route.model, "agent": route.agent,
                        "risk": state["risk_tier"].lower()})
    move_project_status(issue, map_state_to_column(state["status"]))
    if can_assign_copilot(issue, state, route):
        graphql_assign_copilot(issue.node_id)          # GraphQL only -- KI-075
        move_project_status(issue, "In Progress")
    else:
        move_project_status(issue, "Ready for Trial")
        comment(issue, route.block_reason)

§4 TASK-102 Four-Layer CI Gate Pipeline

Owner: DevOps / Governance · Risk: HIGH · Duration: ~3 days · Closes: pain points 6–11

Purpose

Implement the 4 security layers as CI hard gates in a single workflow agent_gate.yml. Every PR must pass all four to be merge-eligible.

Layer A — Scope Lock

scripts/gates/check_scope.sh

Input:  PR diff vs base branch + state file
Output: exit 0 if every changed file
        is in allowed_scope AND not in forbidden_scope
        exit 1 with per-file reason otherwise

Always-forbidden defaults: .env*, **/secrets/**, **/private_data/commercial/**.

Layer B — Evidence Lock (with AC test binding)

scripts/gates/check_evidence.py

Requires .agent/evidence/<TASK-ID>/evidence.md with 3 sections:

## Commands Executed
$ pytest tests/ml/test_ocr.py -v
$ docker compose run --rm backend pytest ...

## Raw Output
<verbatim stdout/stderr>

## Acceptance Criteria
- [x] ac_ocr_runs (test_ocr_runs_on_sample) -- PASSED
- [x] ac_conf_score (test_confidence_attached) -- PASSED

For each AC with test field, greps Raw Output for <test_fn> .* PASSED. Integration AC (id int_*) requires a docker command line.

Layer C — AI Decision Router (HDR+AI Review)

scripts/gates/check_hdr_review.py + .github/prompts/hdr-review.prompt.md

Input: PR diff + state.acceptance_criteria[] + state.risk_tier

AI reviewer outputs strict JSON:
{
  "verdict": "ตรง|ไม่ตรง",
  "business_logic_summary": "...",
  "code_logic_summary": "...",
  "mismatches": ["..."],
  "risk_final": "LOW|MEDIUM|HIGH|CRITICAL",
  "next_action": "approve|request_changes|escalate_human"
}

Hard rules:
  1) verdict = ไม่ตรง  -> gate FAIL + label needs-rework
  2) risk_final HIGH/CRITICAL -> require approved-by-human label
  3) typo/no-business-impact -> AI handles directly

Goal: ให้ AI review งาน AI ควรทำไปเลย สรุปชัดว่า Business logic กับ Code logic ตรง หรือ ไม่ตรง; ถ้าไม่ตรงตีกลับทันที.

Layer D — Quality Pipeline

Inline in agent_gate.yml:

- ruff check src/ scripts/ tests/
- mypy scripts/ src/backend --ignore-missing-imports
- pytest -q --maxfail=1
- bash   scripts/gates/check_scope.sh
- python scripts/gates/check_evidence.py
- python scripts/gates/check_hdr_review.py

Uses concurrency: gate-PR# so re-runs cancel stale checks.

§7 Definition of Done (Epic 1)

  • Seed issue TASK-501 flows end-to-end: MCP issue creation → state file → project card → Copilot assignment → PR → 4 gates pass → merge → deploy → health → closed-with-proof.
  • One deliberately bad PR is blocked at each of the 4 layers in turn (evidence stored in .agent/evidence/EPIC-1/).
  • Bypass labels auto-expire within 24 hours and leave audit comments.
  • Board mapping check catches renamed/missing project columns.
  • HIGH/CRITICAL tasks require approved-by-human label before merge.
  • docs/AGENT-SKILL-CATALOG.md updated with new gate scripts.
