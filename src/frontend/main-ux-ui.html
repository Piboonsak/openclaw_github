Processing

รัน OCR → สกัดข้อมูล → จัดสมุดบัญชี ต่อเอกสาร (จริง — เรียก pipeline เดียวกับที่ backend ใช้ประมวลผลเอกสารจริง)

หมายเหตุ: ประมวลผลผ่าน Celery background queue จริง (สูงสุด 5 เอกสารพร้อมกัน) — สถานะและ % ที่แสดงคือสถานะจริงจาก backend ไม่ใช่ข้อมูลตัวอย่าง
โหมดสแกนรายการสินค้า (line-item) เปิดอยู่สำหรับบริษัทนี้: Processing ปัจจุบันสกัดและให้ยืนยันข้อมูลส่วนหัว (header)ได้เต็มรูปแบบแล้ว ส่วนการสกัด/ยืนยันรายการสินค้าราย line-item (Epic 9) ยังไม่เปิดใช้งานปลายทาง — เอกสารจะผ่าน header-only ตามปกติ และจะต้องยืนยัน line-item เพิ่มเมื่อ backend line-item extraction พร้อม (ยังไม่รวมในรอบนี้)
